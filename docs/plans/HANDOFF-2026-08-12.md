## Verification record (why to trust this code)

Every phase ran adversarial verify waves with cross-provider refuters
(the model that wrote code never re-verified its own fixes). ~29
findings total, ALL fixed or explicitly waived with a recorded reason.
The ones worth knowing about when touching the code:

- **Claims/leases**: sweep is set-based with write-time predicate
  re-checks; `lapsed` state keeps delivery counts durable; `release()`
  flips to lapsed/0 (NEVER delete — a deleted claim row hid the message
  below every process's claim frontier); frontier cache key carries
  (st_dev, st_ino).
- **ravend**: strict bodies everywhere, bounded ints, GETs never write,
  all store work off the event loop, SSE drain-capped with forced
  re-read, non-loopback bind requires `--yes-expose`.
- **Policy/harness**: ack once per completed boundary (per-prompt ack
  LOST messages); delivered watermark stops redelivery storms; digest
  budget-capped; 8K body render truncation; reply_channel==watched
  channel refused (feedback loop). The data-framing renderer survived a
  dedicated frame-escape attack round — the `[esc]`-splice mechanism is
  load-bearing; read policy.py's render section before touching markers.
- One waiver on record: claim_next's candidate search still walks the
  terminal-claim backlog per cold call (fine at P1 scale; frontier
  covers warm calls).
